# Объём v1 (п. 2.1 ревью)

**Статус: принято.** README фиксирует: «Параллельный каскад (два сервера) в v1 не входит». Код v1 строится на этом.

- Одна сессия — одно соединение к одному серверу: TLS 1.3 по TCP (`h2`) или QUIC (`h3`).
- Оба направления трафика туннеля идут по этому соединению.
- Пробник умеет измерять каскад (роли целей, парная проба), чтобы решение о v2 опиралось на данные, но VPN v1 его не использует.

Что сделано, чтобы каскад можно было добавить позже без смены формата:

- Типы кадров `0x40..=0x4F` и TLV `0x000C`/`0x000D` остаются зарезервированными (так уже в `astp-types`).
- Привязка аутентификации к каналу делается на каждом соединении отдельно (экспортёр TLS этого соединения), а не к `session_id`. Для каскада это обязательное условие (см. [split-path.md](split-path.md)).
- Флаг `KEY_EPOCH` в v1 не используется: смену ключей делает TLS/QUIC. Кадр с этим флагом — ошибка протокола; номер эпохи оставлен для будущего внутреннего шифрования плеч каскада.

# TUN, адреса и маршруты

**Статус: предложение.** Код: `astp-tun`, `astp-server`, `astp-client`. Только Linux.

## Устройство

- `/dev/net/tun`, `IFF_TUN | IFF_NO_PI`: из устройства читаются и в него пишутся голые IP-пакеты. Версия берётся из первого полубайта: 4 → `TUN_IPV4`, 6 → `TUN_IPV6`, остальное отбрасывается.
- Нужен `CAP_NET_ADMIN`.
- Адреса, MTU и маршруты настраиваются вызовом `ip` (iproute2) — так их видно и понятно администратору; netlink напрямую — возможная замена позже.

## Сервер

- Одно устройство (`astp0` по умолчанию) с адресом шлюза туннеля, например `10.77.0.1/24`.
- У каждого клиента в конфигурации статический адрес туннеля (`address4`, необязательно `address6`). Пул и аренда адресов в v1 не нужны: адрес закреплён за ключом.
- Пакет из TUN уходит в сессию, которой выдан адрес назначения; сессии нет — пакет отбрасывается.
- Пакет из сессии пишется в TUN, только если адрес источника — выданный этому клиенту (защита от подмены).
- Выход в интернет (NAT, `net.ipv4.ip_forward=1`) настраивает администратор: в `deploy/` есть пример. Сервер правила межсетевого экрана не трогает.

## Клиент

- Получает в `CONFIG`: `addr4`/`addr6` с префиксом, `mtu`, `dns4`/`dns6`, `route4`/`route6` (с флагом включить/исключить), `keepalive`, `idle_timeout`, `session_id`.
- Создаёт TUN, назначает адрес и MTU, добавляет маршруты. Маршрут «включить» идёт через TUN; «исключить» — через прежний шлюз.
- Перед маршрутом по умолчанию через туннель добавляет маршрут к самому серверу через прежний шлюз (`ip route get <server>`), иначе соединение туннеля ушло бы в туннель.
- DNS: при флаге `--set-dns` и наличии `resolvectl` назначает серверы DNS на интерфейс туннеля; иначе только пишет их в журнал.
- При выходе удаляет добавленные маршруты; устройство исчезает вместе с процессом.

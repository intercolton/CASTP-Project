# Архитектура

Документ фиксирует устройство репозитория на старте. Сетевые измерения не заменяются демонстрационными данными: неготовый механизм помечается как нереализованный, а не как успешный тест.

## Компоненты

| Крейт | Роль | Состояние |
|---|---|---|
| `probe-common` | Схема JSONL, коды ошибок, TOML, ротация журнала | Есть |
| `probe-client` | Пробы и CLI `astp-probe` | Есть: `test`, `status`, `run`, `report` |
| `probe-server` | TCP/TLS/HTTP/2 на одном порту, QUIC/HTTP/3 на UDP | Есть |
| `probe-analyzer` | Слияние клиентских и серверных событий, статистика | Есть |
| `probe-report` | Текстовый и HTML-отчёт | Есть |

## Библиотеки

Свой TLS и свой QUIC не пишем.

| Задача | Библиотека |
|---|---|
| Асинхронный ввод-вывод | tokio |
| TLS 1.3 | rustls 0.23, кольцо ring, tokio-rustls |
| HTTP/1.1 и HTTP/2 | hyper 1 |
| QUIC | quinn 0.11 |
| HTTP/3 | h3 0.0.8 и h3-quinn 0.0.10 |

Поддержка HTTP/3 считается рабочей только после прохождения интеграционного теста на localhost, не по факту зависимости в `Cargo.toml`.

## Порты

TCP/TLS/HTTP/2 делят один TCP-порт, QUIC слушает UDP с тем же номером порта и не мешает TCP. В примерах это 8443: порт 443 (TCP и UDP) на узле занимает шлюз ASTP-M.

Раскладка портов на каждом узле каскада (аплоад-узел и даунлоад-узел одинаково):

| Порт | Протокол | Кто |
|---|---|---|
| 443 | TCP + UDP | шлюз ASTP-M (`h2` / `h3`) |
| 8443 | TCP + UDP | сервер пробника (`astp-probe-server`) |
| 127.0.0.1:9443 | TCP | административный приём пробника (зарезервирован) |

Цели клиента пробника указывают `port = 8443` и `quic_port = 8443`. Значение по умолчанию в схеме и у `astp-probe test --port` — по-прежнему 443, для пробника на отдельной машине. Административный приём телеметрии задуман на отдельном адресе с отдельным токеном. Этот приём ещё не написан, секция `[admin]` в конфигурации уже зарезервирована.

## Идентификация теста

Клиент передаёт `test_id` в заголовке `x-astp-test-id` и в query. Сервер пишет событие с тем же идентификатором, и по нему позже стыкуются две стороны. Голый TCP-accept получает собственный идентификатор: до TLS клиент ещё не может передать свой `test_id` по тому же байтовому потоку, не сломав ClientHello.

## Вне этой версии

Пробник не содержит VPN, TUN и handshake ASTP-M: они живут в крейтах `astp-*` (см. [design/](design/README.md)). MASQUE, ротация IP и панель пользователей не входят ни в пробник, ни в VPN v1.
